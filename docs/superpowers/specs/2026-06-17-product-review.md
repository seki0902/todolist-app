# FocusFlow 产品评审 — 2026-06-17

> 评审人：产品经理视角
> 状态：待讨论优先级
> 结论：引擎不错，产品不存在

---

## 核心判断

FocusFlow 有一个还不错的任务管理引擎（SQLite、IPC、父子任务、正则 AI 解析、循环任务、测试体系），但引擎之上缺了一层——**用户如何发现、理解、并养成使用习惯。** 不解决这层，加再多 feature 都是浪费。

唯一差异化是 AI 智能解析。如果用户感知不到它，产品跟 Todoist 没有区别——只有更粗糙。

---

## P0 — 第一天就会赶走用户

### 1. 没有 onboarding

用户打开应用 → 空白聚焦视图 → 不知道能干什么。没有 tooltip、没有示例数据、没有引导流程。一个生产力工具需要 3 秒让用户理解「我能用它做什么」，FocusFlow 需要用户自己探索。

**修复方向**: 首次启动自动进入任务列表，SmartInput 获取焦点，光标闪烁在 textarea 里，示例直接可见。

### 2. 默认视图是空的聚焦页

聚焦模式应该是有任务之后才有意义的东西。首次打开进聚焦模式 = 让用户第一天就感受到「这应用对我没用」。

**修复方向**: 默认视图改为任务列表。聚焦模式只在今日有活跃任务时才有意义。甚至可以在没有任务时把聚焦模式替换为 onboarding 卡片。

### 3. AI 解析（唯一差异化）被藏起来

SmartInput 在任务列表页的搜索框上方，紫色虚线框里。用户得先知道「全部任务」是什么，然后发现搜索框上面有个 textarea。这个发现路径太长。AI 解析应该是全局入口——打开应用第一眼看到的就是它。

**修复方向**: SmartInput 提升为全局入口，可通过热键唤起、可嵌在聚焦视图顶部。示例文案始终可见。

### 4. 没有触发用户回来的机制

用户关掉应用后，没有任何东西提醒他回来。没有推送、没有每日摘要、没有邮件。桌面端任务管理器的天然劣势——用户不主动打开就完全不可见。

当前的 `reminder.service.ts` 只检查 `due_time` 到了没。但如果用户设了 5 个今天的任务，今天打开之前这些任务不会主动找他。

**修复方向**: 系统通知每日摘要（上午 9 点：「今天有 5 个任务」），overdue 提醒，番茄钟完成后的正向反馈。长期需要移动端。

## P1 — 功能逻辑混乱

### 5. 三套日历互相独立

| 组件 | 在哪 | 干什么 |
|------|------|--------|
| `MonthGrid` | StatsView → 日历 tab | 月度概览，点日期看当天任务 |
| `WeekStrip` | TaskList 顶部弹出 | 横向周选择器，选日期筛选任务 |
| `DayStrip` | TaskList 常驻 | 今日进度条 + 任务计数 |

用户心里只有一个「日历」的概念。你给了三个，它们独立工作、互不知晓。循环任务虚拟展开只在 MonthGrid 里做了，WeekStrip 和 DayStrip 没有。

**修复方向**: 日历升级为一级导航（侧边栏独立入口），统一 MonthGrid + WeekStrip 为一套月/周/日切换。DayStrip 保留但仅作为今日摘要。

### 6. 番茄钟跟任务进度不联动

聚焦视图的 Hero Card 里最大的 CTA 是「开始番茄钟」。但完成番茄钟后，任务进度不变——用户需要回到任务列表手动拖进度条。番茄钟和任务是两个平行世界。

产品定位模糊：如果番茄钟是核心 workflow，它应该跟任务进度自动联动（完成一个番茄钟 = +25% 对应当前任务）。如果番茄钟只是小工具，它不应该在聚焦视图占据 CTA 位置。

**修复方向**: 番茄钟完成 → 当前聚焦任务自动推进度（如 +25% / pomodoro）。番茄钟始终关联一个任务。

### 7. 统计只有数据没有洞察

优先级饼图、状态柱状图、周趋势折线图——很漂亮。但用户看着它们，下一步应该做什么？

好的统计页回答：「你最近效率变高了还是变低了？哪些任务一直在拖延？建议把 X 个 overdue 任务重新安排。」

**修复方向**: 每张图表配一行自然语言解读。增加「拖延任务」「预估 vs 实际时间」等 actionable 指标。

### 8. 每日迁移弹窗触发条件太机械

当前逻辑：「昨天有未完成任务 + 今天第一次打开」→ 弹。但：
- 半夜 12:01 打开？弹，但用户只是瞟一眼
- 昨天全完成？不弹，用户直接面对空页面，无感知

**修复方向**: 判断用户是否「真的在开始新的一天」——结合时间（比如早上 6-10 点）+ 昨日遗留数据。不仅迁移任务，也展示昨日总结。

## P2 — 细节打磨

### 9. 子任务创建方式单一

只能用拖拽一个任务到另一个上来创建父子关系。没有右键菜单、没有「缩进」快捷键、新用户完全不知道可以做子任务。

**修复方向**: Tab 键缩进、右键菜单「转为子任务」、新建任务时可选父任务。

### 10. 子任务折叠交互不完善

父任务左侧有折叠箭头，非父任务左侧是拖拽手柄——同一位置不同图标。折叠后子任务完全消失，没有视觉残留提示。

**修复方向**: 统一左侧交互区。折叠后显示「+N 个子任务」摘要。

### 11. 拖拽排序缺视觉反馈

拖拽时不知道任务会放在目标的前面、后面、还是变成子任务。结果位置常常不是用户想要的。

**修复方向**: 拖拽时显示插入线（insertion indicator），区分「排序」和「嵌套」。

### 12. 视觉语言不统一

同一个应用里：聚焦视图用 glassmorphism，统计页用扁平卡片，SmartInput 用紫色虚线框，子任务多层缩进有自己的视觉层级。三套视觉语言混在一起，降低产品信任感。

**修复方向**: 选一套设计系统并贯彻。建议收敛到扁平卡片 + 统一圆角 + 统一间距。

### 13. 便签是功能癌

便签有独立的 BrowserWindow、深色/浅色、透明度、指南横幅——一个完整的小产品寄生在主应用里。但它跟任务工作流没有关系。用户甚至不知道它存在。要么整合进 workflow（任务可以 pin 到桌面），要么砍掉。

## P3 — 文案与命名

| 现状 | 问题 | 建议 |
|------|------|------|
| 「聚焦模式」 | 新用户不理解 | 「今日」 |
| 「模板」 | 不知道是什么 | 「任务模板」+ 一句解释 |
| 「管理」 | 用户以为是设置 | 拆分为「模板」和「分类管理」 |
| 「显示已归档」 | 跟「取消」混用 | 统一用「归档」，取消状态叫「已归档」 |
| 「Ctrl+Enter 快速解析」 | 10px 字，没人看到 | 移到 SmartInput 右侧按钮旁边 |
| 取消 → 归档 | 同一状态两个名字 | 统一为「归档」(archived) |

## 做对了的（别删）

- **正则 AI 解析引擎** — 中文覆盖好（每周/每天/每月/明天/分钟/提醒），离线可用
- **父子任务 + 进度汇总** — 设计最成熟的部分
- **软删除（归档）** — 不丢数据
- **循环任务系统** — 推进逻辑正确，目标日期同步到位
- **键盘快捷键** — Ctrl+1/2/3, Ctrl+N, Ctrl+F，虽然没人知道但有了
- **测试** — 11 tests，纯逻辑 + 组件
- **Brooks-Lint 100/100** — 代码质量不错

## 产品路线建议

```
Phase 1: 止血（P0）
  首次体验 + 默认视图 + AI 入口 + 每日摘要通知

Phase 2: 闭环（P1 + 登录）
  Supabase 登录 + 数据同步 + 番茄钟联动 + 日历统一 + 统计洞察

Phase 3: 打磨（P2-P3）
  视觉统一 + 交互细节 + 子任务增强 + 便签整合

Phase 4: 增长
  AI Worker (DeepSeek) + 移动端 + 分享/协作
```
